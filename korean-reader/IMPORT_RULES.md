# 小说导入与翻译：原文排版保留规范

**强制执行：以后所有用户提供的韩文小说，不只是保存原文文字，还必须尽可能保留原文排版和非文字内容。** 先审计 DOM 结构，再翻译，最后上传、渲染并核验；严禁把“译文不为空”作为“正文完整”唯一标准。

## 导入前核对

1. 统计原文所有可见内容节点，不能只取非空的 `<p>`：包括 `p`、`h1–h6`、`blockquote`、`span`、`div`、`figure`、`img`、`iframe`、`video`、`br` 等。遍历时依照原文 DOM 顺序，尤其注意独立于 p 的文字、短信、聊天记录。
2. 保留原文的**段落边界、段首缩进、空白段落、空行数量、章节标题、居中/左右对齐、引用、强调和场景分隔符**。不要把短句合并成一段，也不要把一段擅自拆成数段。原文用空白制造停顿时，不能因为空段没有文字就删除。
3. 原文中有聊天气泡、论坛、推文、短讯、评论、网页截图等特殊呈现时，保留原来的**左右方向、颜色、时间和顺序**；文字和译文应继续与对应气泡关联。
4. 逐一核查图片：包括真实 `img`、`data:image`、相对/绝对图片 URL、背景图片以及其他被截图保存的嵌入元素。图片必须位于原文所在位置；没有源图时明确记为“原文图片缺失”，不要用 AI 图或无关照片替代。HTML 不含图片时不可凭空声称原作本来没有图，只能说“该离线文件不含可恢复的图片”。
5. 嵌入视频/音乐应按原文位置保存，不能只留在 JSON 的未显示元数据中。没有可恢复的媒体时标注缺失。
6. 一个上传文件含多个章节时，严格按原文的章节分隔点拆分，分隔处的标题/空行也要恢复。
7. 导入时原文每一条可见内容（文字、空行、标题、媒体）都应有**可复查的记录类型和原始顺序**。可以存结构化布局属性，不直接信任原文任意 CSS/HTML。
8. 网站现在采用**中文单语阅读**，不再设计英文／韩文对照、逐段翻译开关、英语点词、IPA 或朗读。保留中文阅读所需的书架、章节切换、阅读位置、字体和正文搜索。原文结构信息继续保留以供核验。

## 翻译和验收

- 默认用 `조승연→曹承衍`、`김우석→金宇硕`；对粉丝发言直译，对小说允许忠实且通顺的文艺翻译，但不得省去情节或改写关系。
- 译文与每个原文文本节点逐一对齐，遇到翻译限制或图片资源缺失必须标明，不能将韩文照抄当成中文或英文译完。
- **翻译完成后再作为完成作品上架**。不得把“仅导入韩文”“翻了一部分”写为 `translationStatus: complete`。
- 上传前后各做一次核验：按原始 DOM 的顺序对比**文本单位数、空白结构数、标题数、图片数、嵌入媒体数、特殊气泡数及方向**；每一项都要报告，任何遗漏要修复或明确披露。
- 修正已有作品时同样遵循，不要只补文字而丢失样式、插图或来源信息。

本规范来自读者对原文排版完整性的一贯要求，适用于之后全部小说导入。
